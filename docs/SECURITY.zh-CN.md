# 安全报告政策

## 私下报告本软件漏洞

如果怀疑 **XSS Audit Desktop 本身**存在漏洞，请通过 **[GitHub 私密漏洞报告](https://github.com/Serennity007/xss-audit-desktop/security/advisories/new)** 联系仓库维护者，避免在公开 Issue 中暴露细节。

请提供受影响版本或源码 commit、操作系统、程序入口、最小复现、预期安全边界、实际行为与影响。尽量使用构造项目或压缩包，移除真实密钥和无关私有数据。

适用案例包括：压缩包解压越界、意外执行导入代码、凭据泄漏、报告导出引入意外活动内容等。说明复现所需条件，只在自己拥有或获得授权的环境测试。

不安全的审计指令、恶意仓库内容、意外包含的私有数据、越界读取，以及未经同意发送源码，也属于本软件的安全报告范围。

调查期间，请在私密报告中协调披露。响应时间取决于维护者可用时间，最小复现有助于判断；本仓库未设置漏洞赏金计划。

## 版本范围

优先使用**最新正式版本**，目前为 `v0.3.0`；源码问题须注明具体 commit。历史 `v0.1.x`／`v0.2.x` 的问题请先核对能否在最新版复现。此政策不承诺旧版回补或固定支持周期，版本记录见 [CHANGELOG](../CHANGELOG.md)。

## 区分检测反馈与软件漏洞

扫描其他项目产生的线索，不表示本工具本身有漏洞。其他项目的漏洞应通过其维护者的披露流程反馈。去敏后的疑似误报或漏报案例，可使用[检测反馈表单](https://github.com/Serennity007/xss-audit-desktop/issues/new?template=detection_feedback.yml)。

## 源码与报告处理

本地扫描读取源码，不执行项目代码或安装项目依赖；GitHub 导入下载公开仓库快照。可选 AI 审核在桌面确认或 CLI 显式使用 `--ai` 后，才将选定源码范围发送到配置的服务商。

分享前请检查源码和报告，敏感值遮蔽不能覆盖所有凭据。应用不保存 API Key，服务商控制接口访问、计费和数据保留。详见[使用指南](USAGE.zh-CN.md#ai-辅助审计)与[分析边界](ANALYSIS.md)。
